# ai-hotspot-radar · AI 热点雷达

个人使用的 AI 选题工具。已实现公开采集、SQLite 历史快照、趋势与中文排行榜，以及独立的 AI 热点解读、三个视频角度、选题状态和预算控制。第四阶段包含视频制作工作台，以及研究计划确认、Tavily 搜索提取、可追溯证据和人工审核的研究报告。A/B 评分继续使用本地确定性规则；AI 研究不覆盖评分或旧选题结果。

## 环境与安装

已在 Windows 11、Python 3.13.12 上安装并运行。直接依赖固定为 Streamlit 1.66.1、requests 2.34.2、python-dotenv 1.2.4、pytest 9.2.0、jsonschema 4.26.0；SQLite 使用标准库。第三期将环境中已有的 jsonschema 明确列为直接依赖，不引入模型 SDK。

在本项目目录打开 PowerShell，执行：

```powershell
# 进入项目根目录。
Set-Location 'E:\one\ai-hotspot-radar'

# 首次配置时创建独立虚拟环境；已有 .venv 可跳过。
py -3.13 -m venv .venv

# 仅向项目虚拟环境安装依赖，不修改全局 Python。
.\.venv\Scripts\python.exe -m pip install -r requirements.txt

# 可选：仅在 .env 不存在时复制配置示例，避免覆盖已有密钥。
if (-not (Test-Path -LiteralPath '.env')) {
    Copy-Item -LiteralPath '.env.example' -Destination '.env'
}
```

无需激活虚拟环境，直接使用其中的解释器即可，避免 PowerShell 执行策略影响。其他操作系统可将解释器路径换成 `.venv/bin/python`。

## 启动与使用

```powershell
# 在本机启动网页；关闭匿名使用统计，日志默认输出到当前终端。
.\.venv\Scripts\python.exe -m streamlit run app.py --server.address 127.0.0.1 --server.port 8501 --server.headless true --browser.gatherUsageStats false
```

浏览器打开 [AI 热点雷达](http://127.0.0.1:8501)。终端按 `Ctrl+C` 停止服务。

1. 页面先展示 SQLite 中的历史记录；空数据库会显示提示，不会自动请求 API。
2. 点击“手动刷新”采集两个来源、保存新快照并更新评分，页面分别显示新增、更新、去重、快照数量及错误。
3. 点击“重新计算评分”只使用本地 SQLite 更新评分，不联网、不新增快照。调整规则后也使用此入口。
4. 使用关键词搜索标题、摘要或链接，按主来源、类别筛选，按综合分、两类评分或七个分项排序；每页最多 20 条。
5. 展开“评分依据”查看维度分、原始/有效权重、命中词、输入时间和规则参数；展开“历史热度变化”查看真实快照。
6. 点击“打开原始链接”访问来源提供的页面；没有外链的 HN 帖子打开其原讨论。“最近采集任务”保留来源任务状态。
7. 在侧栏选择“AI 选题分析”进入第三期功能；仅明确确认并点击分析按钮才调用模型，普通查看和筛选不收费。
8. 在侧栏选择“视频制作工作台”，从已有视频选题创建制作任务，管理名称、备注、人工状态及内容历史。详情中的资料研究只有点击明确的模型操作才调用 DeepSeek，确认计划并点击搜索后才调用 Tavily。

网页展示标题、来源、类别、摘要、发布时间、首次采集时间和来源专属热度。时间均为 UTC，缺失字段显示“暂无”，不会使用虚构指标补齐。

## 采集口径

| 来源 | 官方入口与范围 | 原始指标 | 时间字段 |
| --- | --- | --- | --- |
| GitHub | [仓库搜索 API](https://docs.github.com/en/rest/search/search#search-repositories)；`topic:artificial-intelligence pushed:>=最近7天 archived:false`，按 Stars 降序取前 30 条 | `stargazers_count`，累计 Stars | `created_at`，仓库创建时间，可能远早于 7 天 |
| Hacker News | [官方 Firebase API](https://github.com/HackerNews/API)；热门列表前 60 条，按标题和正文中的 AI 关键词筛选，排除已删除、失效与超过 7 天的帖子 | `score`，HN 积分 | `time`，帖子发布时间；缺失时保留为空并警告 |

HN 关键词包括 AI、LLM、GPT、Claude、Qwen、Ollama、人工智能、大模型等；英文缩写使用单词边界，避免将 `email`、`railway` 误判为 AI。样本和关键词筛选会有遗漏或误匹配，范围不限于新发布的产品。

GitHub Stars 不是最近的增长量，HN 积分也不与 Stars 直接比较。第二期先按来源各自的规则锚点归一化，再进行评分排序；有合格历史快照时才计算观察区间内的真实变化。这是有限样本的选题参考，不是全网热榜或播放量预测。

请求使用 15 秒连接超时、15 秒单次读取超时，为较慢连接和代理握手留出余量；HN 最多 6 个并发详情请求。每次刷新 GitHub 使用 1 次搜索请求，HN 最多 61 次请求。不会对限流自动重试，也不会绕过登录、验证码或其他访问限制。

## 存储与去重

SQLite 表 `hotspots` 保留一期全部字段及语义：`id`、`title`、`url`、`source`、`summary`、`published_at`、`collected_at`、`score`、`category`、内部去重键和搜索文本。`id` 由数据库生成，可选字段允许为空。第二期增加 `primary_source_key`，并新增任务、快照与评分表，详见下文。

- URL：规范化主机和默认端口，删除片段、`utm_*`、`fbclid`、`gclid` 等明确跟踪参数。保留协议、路径大小写、尾斜线、业务参数及同名参数顺序，避免误合并。
- 标题：Unicode NFKC 规范化、大小写折叠、压缩空白。
- 标题或规范化 URL 任一相同即视为重复，数据库对两个键分别建立唯一约束。
- 同来源、同 URL 再次采集时更新标题、摘要、发布时间及指标，保留首次采集时间和首个原始链接。指标缺失时保存为空。
- 不同链接但同标题，或一次更新同时命中不同记录时，跳过新记录并保留首条。第二期的跨来源同链接不新增热点，但分别保存来源快照；不同 HN 帖子使用不同对象 ID。来源筛选仍使用热点主来源，不会将 HN 积分写进 GitHub Stars。
- 每个来源单独事务保存；某来源请求或保存失败时，其他来源继续处理。HN 单条详情失败也会尽量保存其余帖子。

## 第二阶段：迁移与历史快照

第二期版本通过 SQLite backup API 生成同目录备份并将 `user_version` 从 0 更新为 2。第三期升级至 v3，4.1 升级至 v4；当前 4.2.1 支持 v0/v2/v3/v4→v5 的事务迁移，备份名称为 `data/hotspots.pre-v5-时间戳-随机后缀.sqlite3`。重启不重复迁移，不删除原数据或改变已有 ID。未知的新版本数据库会拒绝打开，避免静默降级。

| 表 | 用途 |
| --- | --- |
| `hotspots` | 保留旧字段及去重约束，增加可空的主来源稳定对象 ID |
| `collection_runs` | 周期 ID + 来源唯一；保存起止时间、成功/部分成功/失败、数量、警告及安全错误摘要 |
| `hotspot_snapshots` | 保存热点、周期、来源、对象 ID、实际采集时间、来源链接及可获取的原始指标 |
| `hotspot_scores` | 保存当前 A/B/综合分、规则版本、计算时间、完整证据 JSON 和过期标记 |

GitHub 快照保存 Stars、Forks、创建及推送时间；HN 保存积分、讨论数和发布时间。不支持或未提供的指标是 `NULL`，真实零值是 `0`。请求失败仅写任务状态，不写假零快照。快照只追加，不覆盖。

每次刷新生成一个周期 ID。同周期、同热点、同来源对象只保存首条；同周期成功任务重入不再采集。GitHub 使用官方仓库 ID，HN 使用帖子 ID；同一外链的不同帖子不拼成一条趋势。跨来源快照可以关联同一热点，但排行榜只使用其主来源对象序列，其他序列在历史表中单独标识。

旧库的首次采集时间与后来覆盖的 `score` 可能不属于同一观测，**不会把旧指标补写为历史快照**。从迁移后的成功采集开始积累。尚无新快照的旧指标显示为“一期保留指标，实际观测时间未知”，不计入当前热度。

需要恢复时，先停止服务，保留当前库，再将迁移前备份复制到新文件并将 `AI_RADAR_DB_PATH` 指向该副本。当前程序再次打开旧版副本会重新迁移；如需一期原始结构，应使用对应一期代码读取备份。不要在服务写入时直接覆盖数据库。

## 第二阶段：趋势与评分规则

所有规则位于 `services/scoring_rules.py`，修改后点击“重新计算评分”。规则版本、权重、锚点、时间阈值及实际命中词会随每条评分保存。以下规则是启发式选题参考，尚未使用播放量数据验证。

**趋势**：只比较同来源、同对象的 Stars 或 HN 积分。以最新快照为终点，在此前 7 天内找至少相隔 1 小时、最接近 24 小时的有效基线。`变化量 = 最新值 - 基线值`，`折算日均变化 = 变化量 / 实际间隔天数`；展示真实观察区间，不声称是完整自然日统计或增长加速度。

不足两次有效观测、间隔过短或不在窗口内时，显示“趋势数据不足”，趋势维度为空。最新指标缺失时不回退旧值；超过 48 小时显示“趋势数据过期”，不用于当前热度或增长评分。零基线仍能计算实际增量，但百分比不可计算；真实下降保留负值。三次以上有效观测覆盖至少 24 小时为中等证据，否则为低置信；这不是统计学置信概率。

**A：热度与趋势分，满分 100**：

| 维度 | 初始权重 | 规则 |
| --- | --- | --- |
| 当前热度 | 35% | `100 × min(1, log(1+x)/log(1+R))`；GitHub 的 R=100000 Stars，HN 的 R=1000 积分 |
| 近期增长 | 40% | 同上对日均变化使用增长锚点 G：GitHub 1000 Stars/日、HN 100 积分/日；负增长此维度为 0，原始负增量仍展示 |
| 时效性 | 25% | `100 × 2^(-年龄天数/7)`；GitHub 使用真实推送时间，HN 使用帖子发布时间 |

Stars 和积分先使用各自来源的锚点；锚点是可调整的规则参数，不是经校准的分位数，也不代表不同平台具有相同受众规模。

**B：视频选题价值分，满分 100**：

| 维度 | 初始权重 | 规则 |
| --- | --- | --- |
| 实用价值 | 30% | 有可分析文本时基础 20；命中编程辅助、效率/自动化、创作/数据处理三组场景，各加 25，最高 95 |
| 可演示性 | 25% | 基础 20；演示/Playground 组 +35，CLI/API/界面组 +25，教程/示例组 +20，最高 100 |
| 新颖性代理 | 20% | `100 × 2^(-创建或发布时间年龄天数/30)`；表示新发布程度，不推断原创性；不使用推送时间替代创建时间 |
| 主题匹配 | 25% | 明确 AI 词 40、工具词 30、编程词 30；无命中是规则证据不足，不等于输入缺失 |

英文词使用边界匹配，避免将 `email`、`railway` 或 `client` 的子串误当 AI/CLI。视频规则只分析标题和摘要，命中词不表示产品已亲测。完全没有可分析文本时，对应维度为空。未来或无效日期不获得满分。

**缺失降级**：`得分 = Σ(可用维度分 × 原权重) / Σ(可用原权重)`。缺失维度不赋零或满分，保留可用权重覆盖率、有效权重及缺失原因；全部缺失时总分为空。趋势不足、覆盖不全或证据少时标记暂定分/低置信。高暂定分不能理解为证据完整。

**综合分**：只有 A、B 都可计算时使用 `0.5 × A + 0.5 × B`，否则为空；不隐藏添加置信系数。空分排最后，同分按最近主来源采集时间和 ID 稳定排序。筛选不会改变归一化锚点或已有分数。

**类别**：文本命中编程词得到“AI 编程”；同时命中 AI 词与工具词得到“AI 工具”；GitHub 来源得到“开源项目”；其余为“AI 讨论/其他”。标签可重叠，依据随评分保存；一期 `category` 字段保留。

评分在手动刷新之后或明确点击重算时更新，日常筛选和页面重跑只读已保存评分。原始指标另行读取最新真实快照。输入变化、规则变化、重算失败或评分超过 1 小时未重算时，页面提示评分过期；不会自动联网或反复评分。评分计算失败不回滚已保存快照，旧评分保留并标记过期；并发刷新改变输入时拒绝将旧输入计算结果标成最新。

本期保留一期有限采样范围，不额外遍历离开榜单的全部历史仓库/帖子；离开采样范围不等于热度归零。最近采集时间与过期状态用于揭示这项覆盖限制。

## 常见问题

**GitHub 超时、无法连接或认证失败**：检查网络、代理和 `.env` 的 Token；Token 可留空。认证失败时修正或移除无效 Token。应用会提示错误，并继续处理 HN。不要关闭证书校验来规避网络错误。

**API 提示限流**：遵循页面中的等待提示稍后再刷新，避免连续点击。[GitHub 搜索限流文档](https://docs.github.com/en/rest/search/search#rate-limit)说明了搜索配额；可选 Token 需要配置后才会随请求发送。

**本次没有匹配内容**：HN 只检查前 60 条热门帖，GitHub 只检查指定主题。零匹配可能是正常采样结果；历史数据仍保留。检查来源状态，区分没有匹配与采集失败。

**有分数但趋势不足**：系统会按已有维度算暂定分，并显示覆盖率和低置信。至少隔 1 小时再次刷新同一对象；单独重新评分不能创造历史观测。

**评分待计算或过期**：点击“重新计算评分”，不消耗 API 配额。若原始指标也过期，需手动刷新取得新快照；只重算不会让旧指标变新。

**类别筛选没有记录**：类别由评分规则生成。旧记录尚未计算评分时没有新标签，先重算；标签是文本规则判断，也可能误匹配或漏判。

**数据库无法打开或锁定**：检查 `AI_RADAR_DB_PATH` 是否指向文件、父目录是否可写，以及磁盘空间。数据库连接会等待锁最多 10 秒；请避免其他程序长时间占用写事务。修复后重新运行页面。

**升级后提示数据库版本过高**：先看错误中的实际版本与程序支持版本。旧 Streamlit 进程可能残留升级前的模块引用；停止该项目的旧服务，再使用项目 `.venv` 中的解释器启动。存储入口已改为按需读取当前迁移模块，两页都会显示具体版本原因。不要通过降低 `PRAGMA user_version`、删除数据库或关闭版本检查来处理；确实比程序更新的数据库需要兼容版本程序。

**8501 端口被占用**：启动命令改用 `--server.port 8502`，然后访问对应地址。不要为此停止不相关的程序。

**服务重启后数据不见了**：核对是否改变了 `AI_RADAR_DB_PATH`。相对路径固定以项目根目录为基准；不同数据库路径保存不同历史。

**想从零开始收集**：先停止服务并备份数据库，再将 `AI_RADAR_DB_PATH` 指向新的文件；应用不会自动删除旧库。

7. 使用“历史分析”选择以前结果；展开“本次实际提供的材料”查看输入快照。所有结果均未独立核验，模型不会自动打开来源链接或亲测产品。

## 第三阶段：数据库和预算

迁移前先对真实旧库做副本演练和一致备份。版本3新增 `topic_analyses`、`ai_analysis_runs`、`video_ideas`、`idea_actions`、`ai_budget_settings`，保留前两期所有表及数据。`topic_analyses` 同时承担运行锁，只有 `status=success` 的记录才作为分析历史展示；运行中/费用待确认状态由部分唯一索引阻止同材料并发调用。

每次 HTTP 尝试单独保存模型、版本、实际 usage、价格、预占、状态及安全错误类型。调用已发生但结构/落库失败时，仍记录已取得的 usage；分析与三个选题则在一个事务内成功或全部回滚。A/B 表不在 AI 模块的写入流程中。

金额使用 Decimal 计算，数据库以百万分之一元为整数单位，向上取整。根据服务商 usage：

```text
估算费用 = (缓存命中输入Token × 命中单价
         + 缓存未命中输入Token × 未命中单价
         + 输出Token × 输出单价) / 1,000,000 × 人民币换算系数
```

缓存细分不完整但总输入量可得时，按全部未命中保守估算，并保留原始缺失计量；完全没有 usage 的费用为空，不等于零。

初始 Flash 价格目录使用人民币高峰单价：输入命中0.04元、输入未命中2元、输出8元/百万Token。空闲时段仍按该口径保守估算，**不是服务商最终账单**。价格可能变化，需核对 [DeepSeek 官方价格](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)。

每次请求之前，在 SQLite 写事务中检查“已估算/核对费用 + 未结算预占 + 本次预占”不超过月上限。预占按完整请求字节数、4096 Token包装余量、最大输出Token及适用单价保守计算，并非声称这些是实际Token。每次重试都重新过门禁。

账期按北京时间。默认100元，70%警告、90%高风险、达到上限或本次预占将超额时拒绝发送；自定义上限按相同比例警告。预算可在页面主动保存，允许0元暂停新调用。预算耗尽不影响采集、排行、重算或查看历史。

连接建立超时、429、500/503最多按配置尝试3次，有限退避；认证、权限、余额、参数、截断或非法结构不自动重试。读取超时/发送后断连可能已计费，不默认重发。每个失败尝试若有usage照常计入估算，缺失usage则保留预占。

进程中断或未知费用不会因重启自动释放。在“API 用量、费用与待确认任务”中，先确认原任务确已停止；然后核对服务商账单，填写实际核对金额和至少8字依据后保存。保留原usage、预占、人工核对金额和理由，不删除记录清账。不应在请求仍运行时解除任务锁。

本地限制依赖配置价格及保守预占，不能替代服务商账单。页面分别显示可得Token、估算/核对费用、待确认预占和剩余预算；未知值明确展示为未知。
