## 2. 范围与技术选型声明

沿用 Python、Streamlit、SQLite 和 pytest，不增加第三方依赖、ORM、后台任务或网络服务。不修改采集、评分、AI 分析、预算或费用算法，不执行真实 AI 联调，不创建 Git commit。

采用存储层负责 SQL 与事务、服务层集中负责状态和版本规则、页面负责输入与展示的现有分层。相较为尚未实现的五个模块分别设计业务表，本次采用统一内容对象与完整版本载荷，减少空表及过早限定内容格式；未来模块可增量扩展专有结构。

## 3. 增量数据库结构

目标版本：**v4**，支持新库及 v0/v2/v3 到 v4；只新增制作结构，不修改前三阶段业务表字段或记录。

| 新表 | 主要字段与约束 |
| --- | --- |
| `production_projects` | 自增 ID、`name`、`idea_id` 外键到 `video_ideas.id`、`status`、`notes`、`resume_status`、UTC 创建/更新时间。状态 CHECK；暂停时保存原正常状态；部分唯一索引约束同一 `idea_id` 仅有一个非归档任务。 |
| `production_actions` | ID、任务外键、`action_type`、`previous_status`、`new_status`、操作时间、完整操作详情 JSON。创建、编辑、状态变化及版本操作均追加审计，与对应更新同事务提交。 |
| `production_objects` | ID、任务外键、`content_type`、对象键/名称、创建时间；类型限定 research/script/storyboard/asset/editing_guide；任务＋类型＋对象键唯一。同类模块允许不同内容对象。 |
| `production_versions` | ID、任务与对象关联、对象内递增版本号、完整 JSON 内容、来源、说明、创建时间、恢复来源版本 ID。对象＋版本号唯一；通过外键/复合约束保证任务和对象归属一致，恢复源属于同一对象。 |

索引覆盖任务的来源选题、状态/更新时间、动作的任务/时间、对象的任务/类型，以及版本的对象/版本号。外键不配置级联删除历史。

版本内容支持 JSON 字符串、对象及数组，文本以 JSON 字符串完整保存；拒绝不可序列化值及 NaN/Infinity，不截断为摘要。使用只追加接口和数据库保护防止版本记录被更新或删除；历史操作同样不提供覆盖/删除入口。

不预填研究报告、脚本、分镜、素材或剪辑指导；必要对象在第一次保存真实内容时创建。

## 4. 制作任务与状态规则

- 状态：待开始、资料研究中、脚本制作中、分镜设计中、素材准备中、剪辑准备中、制作完成、已暂停、已归档。内部使用固定状态码，中文标签集中维护。
- 从任意已有视频选题显式创建任务，默认待开始；验证选题存在、名称非空。名称与备注可人工保存。
- 非归档任务均占用选题唯一名额，包括暂停与制作完成；不能靠暂停规避去重。依靠唯一索引和写事务处理重复点击及并发创建。
- 正常状态之间允许人工调整，不把状态选择解释为 AI 已执行。页面明确标识“人工管理状态”，无自动阶段推进。
- 暂停：保存暂停前正常状态并进入已暂停；重复暂停不重复记日志。
- 恢复：仅从已暂停恢复到保存的原状态；清除恢复字段。暂停期间先恢复再调整正常阶段，通用状态入口也走同一服务规则。
- 归档：允许从任意非归档状态归档，作为本期终态；归档后只读查看任务、操作及版本，不再编辑、恢复版本或改状态。原选题可创建新的有效任务，旧任务与版本完整保留。
- 默认列表排除归档任务，提供显式归档历史筛选和详情入口。不存在的 ID 和非法操作返回可展示的错误。
- 状态更新、更新时间与审计必须原子提交；同一状态重复提交不产生伪变更记录。

## 5. 通用版本服务

- 按制作任务、内容类型和对象键创建版本，序号按内容对象独立从 1 递增。
- 保存完整内容、UTC 创建时间、说明和来源：AI 生成、人工修改、人工恢复。AI 来源仅为通用记录能力，本期没有任何生成器或 AI 调用入口。
- 查询对象历史、指定版本详情及任务下已有对象；不能跨任务或跨对象读取后误恢复。
- 恢复操作复制历史版本完整内容，追加当前对象的下一个版本，来源为人工恢复，并记录恢复源 ID；不会回退序号或覆盖任何版本。
- 版本号分配、插入与操作记录在同一写事务完成，覆盖并发保存与事务失败测试。
- 不实现差异可视化、AI 研究、脚本编辑器、素材上传或视频生成。
