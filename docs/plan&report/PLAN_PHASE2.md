## 3. 数据库迁移与快照

迁移前使用 SQLite backup API 生成带时间戳的备份，先在旧库副本验证。迁移在事务内执行，记录 `PRAGMA user_version`；重复启动不重复迁移。保留所有现有热点 ID、记录、唯一约束和首次采集时间，不从旧 `score` 补写快照。

保留 `hotspots` 及其来源字段的含义，只增加可空的主来源对象标识 `primary_source_key`。新增三个有实际用途的表：

| 表 | 内容与用途 |
| --- | --- |
| `collection_runs` | 一次手动刷新中的来源任务：周期 ID、来源、起止时间、成功/部分成功/失败、数量及安全错误摘要；唯一键为周期 ID + 来源 |
| `hotspot_snapshots` | 热点 ID、周期 ID、来源、稳定来源对象标识、实际采集时间、来源原始链接、Stars、Forks、HN 积分、HN 讨论数，以及可获取的发布时间/仓库推送时间等元数据 |
| `hotspot_scores` | 每条热点当前评分：A/B/综合分、类别标签、维度明细 JSON、原始证据、缺失原因、覆盖权重、趋势状态、计算时间、规则版本和所用参数 |

快照规则：

1. 一个手动刷新生成一个周期 ID；同周期、同热点、同来源对象只插入一条快照，重入同周期不覆盖首条。重新计算评分不生成快照。
2. GitHub 使用官方仓库 ID，HN 使用帖子 ID 标识独立时间序列；绝不把指向同一外链的不同 HN 帖子串成一条趋势。
3. 同 URL 跨来源可关联到已有热点，但快照按来源和对象分别保存；排行榜默认只使用该热点主来源的稳定对象序列，其他序列在历史中单独展示，不混合指标。
4. 仅标题重复但 URL 不同仍沿用一期跳过规则，记录去重跳过数，不错误关联其指标。旧记录的主来源对象标识只在首次可靠匹配的新采集中绑定，不猜测旧 HN 帖子 ID。
5. 有效的零值保存为 `0`，未提供或无效字段保存为 `NULL`。请求失败只记录任务失败，不创建全空或零值快照。
6. 热点写入、主来源绑定及对应快照在同一事务完成；来源之间保持故障隔离。快照不更新、不删除。
7. 历史表展示采集时间、来源、对象、各原始指标及变化量；快照可用而趋势窗口不足时仍允许查看原始历史。

## 4. 趋势计算规则

参数集中定义并可测试：最近窗口 7 天、最小间隔 1 小时、目标比较间隔 24 小时、指标过期阈值 48 小时。

- 只处理同来源、同稳定对象的主指标：GitHub Stars 或 HN 积分。
- 最新快照必须含有效主指标；缺失时显示“指标缺失”，不能悄悄用旧值冒充当前值。
- 以最新快照为终点，在之前 7 天中寻找至少相隔 1 小时且主指标有效的快照，优先选择最接近 24 小时间隔的一个作基线。
- `变化量 = 最新值 - 基线值`；`每日变化量 = 变化量 / 实际间隔天数`。展示实际观察区间，日均变化量是按时间折算，并非完整自然日统计。
- 百分比变化只在基线大于 0 时计算；基线为 0 时仍可展示实际增量，百分比标记为不可计算。
- 真实负增量如实显示为下降，不伪装成缺失或正增长。
- 没有合格配对显示“趋势数据不足”，增长速度和趋势维度均为 `NULL`。最新快照超过 48 小时则显示“趋势数据过期”，不作为当前增长评分。
- 仅两点或总跨度不足 24 小时，标记低置信；至少三个有效点且覆盖 24 小时、最新数据不过期，标记中等置信。这里是证据量标签，不是统计学概率，也不能证明增长在加速。

## 5. A：热度与趋势分（0–100）

初始权重为当前热度 0.35、近期增长 0.40、时效性 0.25。权重、阈值及词表集中放在评分规则模块，修改后点击重新计算生效，无需新增网页配置面板。

| 维度 | 计算方式 |
| --- | --- |
| 当前热度 | `100 × min(1, log(1+x)/log(1+R))`；GitHub Stars 的 R=100000，HN 积分的 R=1000。仅用各自来源主指标，不将 Stars 和积分直接放入同一原始排名 |
| 近期增长 | 对有效日均变化量 v：`100 × min(1, log(1+max(v,0))/log(1+G))`；GitHub 的 G=1000 Stars/日，HN 的 G=100 积分/日。负增长此维度为 0，历史仍展示真实负值 |
| 时效性 | `100 × 2^(-年龄天数/7)`；HN 使用帖子发布时间，GitHub 使用真实 `pushed_at` 作为活跃时效，不能把仓库创建时间或首次发现时间当成最近发布 |

R、G 和 7 天半衰期都是可调整的启发式锚点，不是行业统计结论。归一化得到的分数可以用于统一规则排序，但不代表不同平台拥有相同受众规模。

缺失处理：只用有效维度重新归一化权重，即 `分数 = Σ(维度分×原权重)/Σ(可用原权重)`；保留原始覆盖率、有效权重及缺失原因。不将缺失自动赋零或满分；所有维度缺失时总分为空。覆盖不足、趋势不足或数据过期时必须显示“暂定分/低置信”，避免只显示一个看似完整的分数。

超过 48 小时未采集的主指标不再作为“当前热度”评分，但仍展示为带采集时间的历史值。无新快照的旧记录保留展示，不能标成最新指标。

## 6. B：视频选题价值分（0–100）

以标题、摘要和实际 API 元数据作为证据，不访问付费模型，不把规则命中当作已验证的产品能力。以下词组仅为初始词表示例，实施时用明确单词边界和中英文规则测试误匹配。

| 维度及权重 | 可解释的初始规则 |
| --- | --- |
| 实用价值 0.30 | 有可分析文本时基础分 20；命中编程辅助、效率/自动化、创作/数据处理三组使用场景，各加 25，最高 95；记录具体命中的词和文本证据 |
| 可演示性 0.25 | 有可分析文本时基础分 20；命中 demo/playground/演示，加 35；命中 CLI/API/editor/UI/命令行/界面，加 25；命中 quickstart/tutorial/示例/教程，加 20，封顶 100。仅表示文本提示，未亲测可用性 |
| 新颖性代理 0.20 | 使用真实创建/发布时间，`100 × 2^(-年龄天数/30)`；缺少有效时间则为空。明确标注这是“新发布程度代理”，不推断技术原创性；GitHub 不能用最近推送替代创建时间 |
| 主题匹配 0.25 | 明确 AI 词命中 40；明确工具/应用词命中再加 30；明确编程/开发词命中再加 30。没有命中为规则分 0，说明证据不足；不是缺失指标补零 |

文本完全缺失时，依赖文本的维度为空，按与 A 相同的可用权重规则降级。没有关键词命中和根本没有可分析输入是不同情况。

类别作为可多选标签：命中编程主题 → AI 编程；命中 AI 与工具/应用词 → AI 工具；GitHub 仓库 → 开源项目；其余为 AI 讨论/其他。现有 `category` 保留，不覆盖用户原有字段，新增标签随评分保存，并显示分类依据。

## 7. 排行榜与计算流程

- 默认综合分暂定为 `0.5 × A + 0.5 × B`，仅当 A、B 均可计算时展示；任一为空则综合分为空。显示两个分项和各自证据状态，不另加隐藏置信系数。
- 同分按最近成功采集时间、热点 ID 稳定排序；空分排最后。支持按综合分、A 分、B 分，以及各个分项维度排序。
- 保留关键词搜索、来源筛选、原始链接及分页；增加类别标签筛选。来源筛选沿用热点主来源含义，其他来源的历史清楚标识。
- 每条结果展示排名、两类评分、原始指标及采集时间、趋势是否充足；展开可查看权重、维度分、证据、缺失原因、实际变化区间和历史表格。
- “手动刷新”：采集 → 分来源事务保存热点和快照 → 本地评分计算及持久化 → 展示结果。采集/评分分开处理，评分失败不回滚已经成功保存的真实快照。
- “重新计算评分”：只读取 SQLite，更新评分明细与版本，不联网、不新增快照。
- 页面搜索/筛选/重渲染只读取已保存结果，不反复采集或批量评分。迁移后的旧记录若尚无评分，显示待计算，可点击重新计算；不会自动伪造指标。
- 使用标准 logging 记录周期、来源、统计和安全错误类型，不写 Token 或远程异常正文；页面提供可操作的中文错误提示。旧评分计算失败时保留并标记过期，不冒充最新计算结果。
- 刷新入口允许传入周期 ID、时钟与采集器，便于测试及未来定时任务复用；本期不引入调度器。
