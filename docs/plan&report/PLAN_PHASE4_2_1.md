## 3. 必须成立的流程和门禁

流程：选择制作任务 → 生成计划 → 人工编辑/保存 → 确认指定计划版本 → 明确执行搜索/提取 → 整理证据 → 生成报告 → 人工编辑/保存 → 确认指定报告版本 → 允许后续脚本阶段。

1. 生成计划只读来源选题和已有热点/分析材料，可以调用 DeepSeek，但不构造或调用搜索 Provider。
2. 计划确认只确认指定的当前版本，保存任务 ID、计划版本 ID、时间和动作记录；确认本身不搜索。
3. 搜索需用户再点击明确的执行按钮，并在服务层验证当前版本、有效确认、任务状态、执行参数与动作 ID。仅有 UI 禁用按钮不算门禁。
4. 计划保存、重新生成或从历史恢复都会形成新版本，旧确认因版本不再匹配而失效；即使内容相同也不沿用旧版本确认。未保存的页面修改也阻止执行，须先保存并确认最终版本。
5. 搜索执行记录始终绑定当时确认的计划版本；后续计划变化时保留历史结果，但停止其后的网络步骤，不把旧结果当成新计划研究。
6. 整理证据和生成报告均是明确用户操作，受模型预算门禁限制。页面刷新、切换、筛选、查看历史或确认文档不会自动调用模型或搜索。
7. 报告确认绑定当前报告版本及其计划/搜索/证据输入；报告编辑、恢复、重新生成或研究依据更新后，旧确认不能作为新的阶段准入凭据。
8. 在 `ProjectService` 中限制进入脚本及之后阶段；暂停后恢复到这些阶段也执行检查。在通用版本服务中限制新建/恢复后续制作内容，避免绕过状态入口。
9. 通用研究计划/报告恢复与保存需经过同样的结构和引用校验；不能用任意 JSON 加“已确认”字段绕过确认记录。
10. 暂停任务保留只读研究查看，本期暂停期间不执行新的研究写入或外部调用；归档继续只读。确认报告不自动调用或生成脚本。

## 4. 研究计划与版本

复用 `production_objects`：`content_type='research'`，对象键 `plan` 和 `report`；完整 JSON 进入 `production_versions`，不另建计划/报告正文表。

计划字段：研究目标、重点、全局起止日期/不限时间、特别核实事实，以及带稳定问题 ID 的问题数组；每题包含问题文本、关键词数组、推荐来源类型及可选优先域名。

- 支持添加、修改、删除问题，修改关键词、来源类型、日期及重点；每次显式保存追加一个完整版本，原版本可查询。
- 日期必须可解析且起止不矛盾；来源类型、问题 ID、关键词和非空字段统一校验。AI 只能建议来源方向，不把其生成的 URL/域名当作已核实资料。
- 默认生成 3–5 个问题，首期允许最多 10 个；每题关键词组合成一次搜索，不逐个关键词无限扩展。
- 生成/重新生成计划有模型费用预览和明确动作 ID。相同动作重复提交不新增请求；重新生成使用新的主动操作并保留历史。
- 确认记录只追加，当前有效性通过“当前版本＋确认记录”判定，不覆盖确认历史。

## 5. Tavily 搜索与网页提取

官方核对入口见第 12 节。首期固定 basic 深度，关闭自动调参和 Tavily 答案生成；请求使用 `include_usage=true`。优先域名/来源约束来自最终确认计划和实际提供链接，不依靠模型虚构官方身份。

- 默认每题最多 3 个搜索结果，一次研究最多 20 个不同 URL；最多 10 次 search 和 1 次批量 extract，不使用 crawl/research 产品。界面在执行前展示实际调用上限与 credits 估算。
- 每题独立记录查询、结果/失败和关联；结果保留原始 URL。相同 URL 命中不同问题只复用来源并增加关联。
- 根据已保存结果中的公开 HTTP(S) URL 执行 extract；批量响应逐 URL 判断成功/失败，不能以 HTTP 200 判定全部提取成功。空正文、缺失项和失败项分别记录。
- 保存 Tavily 提取文本和搜索摘录两个字段及其类型。提取失败可以保留搜索摘录，但界面与模型材料明确标注“搜索摘要/摘录，正文提取失败”；不声称获得完整原网页。
- 先保存调用状态和服务商实际响应的必要结果，再继续下个步骤。已完成结果不会因后续失败丢失；中断记录不会在重启时自动重发。
- 每个动作有持久唯一 ID 和执行锁；相同动作重入只读结果，主动重新搜索产生新运行。首期 Tavily 调用不自动重试，失败重试由用户显式发起且继续检查有效计划确认。
- 无 Key 时仅显示配置提示，保留本地历史及原有功能；不调用 API，不使用假数据补位。

## 6. 来源、证据和报告可追溯性

### 来源快照

来源保存任务/研究关联、标题、原始 URL、规范化去重键、域名、可获取发布时间、搜索时间、服务商、原始搜索摘录、提取文本及状态。发布时间只接受服务商实际返回值，未知为空。

按“任务＋规范化 URL＋来源内容快照摘要”复用完全相同来源。重新搜索发现正文变化时追加新快照，不覆盖被历史报告引用的正文。问题与来源使用关联表；多个问题可引用同一来源。

### 证据

- 类型：已证实事实、单一来源事实、来源观点、AI 推断、存在争议、待核实。
- 每条证据关联至少一个已保存来源和对应问题；分别保存来源引文、AI 摘要和 AI 推断，不混入原始来源字段。
- 模型只能返回已提供的来源 ID；引文必须能匹配对应已保存正文/摘录，并记录引用文本类型与位置。未知来源、跨任务来源、编造引文和无依据的关键事实拒绝保存为有效证据。
- 多来源交叉支持需有实际引文及来源独立性依据；仅多个链接不能直接认定事实已证实。证据不足时降级为单一来源、争议或待核实；页面标注 AI 分类仍待人工审核。
- 同一轮证据再整理追加一批结果并保留旧批次，报告绑定明确的证据批次。
- 原始来源正文只能由搜索/提取适配器保存，AI 无修改入口。超出模型输入限制时仅发送明确标注范围的摘录，原文完整保存；没有发送的内容不声称已核验。

### 报告

报告包含选题概述、研究目标、核心结论、关键事实、数据及出处、来源观点差异、未核实问题、事实风险和完整来源列表。结论/关键事实/数据必须关联证据 ID，再由服务端解析为来源 ID 和原始链接，在正文展示引用。

模型不负责生成可执行链接或改写来源元数据；完整来源列表由已保存来源生成。人工编辑也保留结构化引用并校验，不能保存不存在的证据。可以编辑各段与事实项、保存新版本、重新生成和查看历史；重新生成不删除证据、来源或旧报告。

结构校验和引文匹配只能证明可追溯，不能证明模型的语义判断真实。报告确认是人工审核动作，页面持续展示材料不足和未核实问题。

## 8. 费用、额度与异常

### DeepSeek

研究计划、证据整理、报告的每次模型尝试，沿用同一 `reserve_attempt`/`finish_attempt`/失败及费用核对流程。预占使用该次实际 Schema 与完整请求体，不能继续按旧选题 Schema 的体积估算。

保留原有有限重试和未知费用策略；失败但返回 usage 仍记模型费用，超时/未知 usage 保留预占。100 元默认月预算及用户当前设置、70%/90%/100%规则不变。新用途不能获得第二份预算或绕过在途锁。

### Tavily

- credits 单独保存在研究调用记录，不混入 Token、人民币模型账本，也不把 credits 臆测成实际人民币账单。
- 在用户执行已确认计划时尝试 `/usage` 检查额度；平时只展示已保存快照，不因渲染查询。已知额度不足则停止，不自动切换更高费用模式或启用付费额度。
- 查询失败或额度字段不明时显示未知，默认停止本次付费搜索；允许用户在页面显式选择按已展示调用上限继续，仍需有效计划确认。
- 逐次保存 API 返回的 credits；缺失或费用不明为 NULL，不写零。API 明确返回 0 时保存实际 0，并说明 Extract 存在累计计量口径，不能据此保证服务商最终免费。
- 统计 search/extract 调用次数、请求状态、来源提取成功/失败数、已知 credits 与未知费用调用数；失败不计成功。
- 额度快照可能被其他客户端消耗，不承诺其为最终余额。本地幂等和调用数量上限控制重复成本，不能替代服务商账户限额。

## 9. 页面范围与安全

在 `pages/production.py` 的任务详情中启用资料研究入口，独立模块按四区组织：

1. 研究计划：生成费用提示、计划编辑、问题增删、版本历史、保存和指定版本确认。
2. 搜索执行：仅有效确认且无未保存修改时显示执行入口，展示参数上限、额度状态、运行进度、问题/结果/提取统计及 credits；重新搜索是独立主动动作。
3. 证据整理：明确按钮触发模型；按问题展示原始来源、引文、AI 摘要/推断、证据类型、交叉核验和失败原因。
4. 研究报告：生成/重新生成、结构化人工编辑、正文引用、完整来源、历史版本及确认；确认后提供进入脚本阶段的人工状态操作，不生成脚本。

安全边界：固定 system 规则与外部材料 JSON 分离；网页、计划、报告均是不可信数据。模型只提交结构化结果，不获得浏览器/文件/命令工具；网络只能由受确认门禁保护的搜索服务执行。链接与日期只能来自保存的来源，页面正文以纯文本/安全引用组件显示，不执行原网页 HTML。错误与日志只保留安全类型和可展示信息，不输出 Key、请求头或远端异常正文。
