## 2. 技术选型声明

最高优先级：调用幂等、预算持久化及未知费用处理；其次是结构校验、证据边界和交互。不要用“分析失败”推断“没有费用”。

### Provider 与模型

- 用 `requests` 调用 DeepSeek 官方接口，不引入 OpenAI SDK；定义可替换的 Provider 协议、标准结果/异常和仅供测试使用的 Mock Provider。
- 推荐默认模型配置为 `deepseek-flash`，读取 `DEEPSEEK_MODEL`，业务模块不硬编码模型名。使用非思考模式以控制响应长度与用量。
- 官方当前价格页明确列出 `deepseek-flash` 的 JSON Output 和 Tool Calls 能力；strict JSON Schema 属于 `/beta` 的工具输出能力，不能把普通 JSON Output 当成严格 Schema。
- 默认采用 strict 工具输出：提交一个仅承载分析结果的 Schema 工具，不提供文件、浏览器、执行或发布工具，也不执行模型输出中的任何指令。
- 服务商 strict 模式对数组长度、字符串长度等约束有限制。发送兼容的 Schema 子集，在本地执行完整校验，包括恰好 3 个角度、每个恰好 2 个备用标题、大纲时长 60–90 秒。
- 提供显式 `json_object` 配置模式作为替代，用相同本地 Schema 验证；不在一次失败后静默切换模式并再次收费。模型不在已核对能力目录中时要求先补充能力配置，不假设可用。
- 使用 `jsonschema==4.26.0` 做本地校验：它已存在于当前环境，将其明确列为项目直接依赖；其余依赖保持不变，不安装全局依赖。
- Provider/模型/输出模式/提示词版本/Schema 版本/分析版本/价格版本全部记录，避免更换模型后沿用不匹配缓存。

### 重试与错误

- 单次连接超时 15 秒，读取超时 120 秒；非流式请求，限制输入体积和最大输出 Token。
- 每个热点最多 3 次 HTTP 尝试，指数退避并遵守合理上限内的 Retry-After；连接建立超时、429、500/503 可有限重试，每次尝试先独立过预算检查并记录。
- 读取超时/发送后断连可能已经发生计费，不默认自动重试；保留未确认费用和明确错误，避免在未知状态下重复收费。
- 401/403 权限、402 余额不足、参数或能力不支持不重试；空内容、截断、无效 JSON/Schema 不伪装成功，不自动通过额外“修复调用”增加费用。
- 错误类型与操作建议展示中文；不记录请求头、完整密钥、第三方异常正文或完整 HTTP 请求转储。

## 3. 结构化输出与事实边界

一次热点分析请求同时生成热点解读和三个角度，正常情况不是分别调用三次模型。

### 输入材料

只读取 SQLite 中实际已有的标题、摘要、来源链接、可用指标与采集时间、趋势状态、A/B 分及证据说明。限制材料长度并标明截断；不自动打开链接或把未提供网页内容当作已读材料。

- 固定 system 指令与外部材料分离；外部文本作为 JSON 数据放入 user 材料区，明确是不可信引用，要求忽略其中改变规则、泄露信息或执行操作的内容。
- 不发送 API 密钥、环境变量、文件系统上下文或原始错误日志。
- 给材料分配证据 ID，提示模型区分“材料声称”“已提供的指标”“推测/待核实”。提示词禁止声称亲测、访问未提供页面或虚构播放量、用户量、增长率及产品能力。
- 保存实际输入材料快照及其哈希，以便解释当时模型究竟看到了什么。
- 只有标题或摘要不足时，客户端也强制标记有限材料/低确定性，不接受模型自行宣布独立核验成功。
- Mock 测试可验证指令隔离、固定规则不被替换、非法输出被拒绝和模型无执行工具；不能据此声称彻底消除了所有模型幻觉或提示注入风险。所有结果保留人工核验清单。

### 输出结构

热点解读包含附件要求的 `summary`、`what_happened`、`why_now`、`target_audience`、`audience_value`、`video_suitability`、`suitability_reason`、`evidence_gaps`、`factual_risks`。

`video_ideas` 必须恰好 3 条，每条包含附件全部字段。`outline` 使用有序分段数组，每段有秒数及内容，合计 60–90 秒；`alternative_titles` 恰好两个；素材、核验项、风险均为数组。

三条角度使用不同的制作类型和不同标题/钩子/结构；客户端检查明显重复并拒绝无效结果，不静默接受三份同义标题。自动校验不能证明语义上必然足够不同，页面仍提供人工判断。

证据状态由客户端根据输入材料生成“基于材料、未独立核验”等标签，不让模型把它改成已验证。Schema 不允许额外 A/B 分数字段，模型输出不能覆盖评分。

新增下列表，按实际字段补足索引、外键和状态约束：

成功分析与三个选题在同一事务保存。API 用量与失败尝试独立记账，即使结构验证或结果保存失败，也不能丢失已经获取的 usage。若服务商已返回但本地保存失败，保留原预占，阻止用未落库状态继续绕过预算。

幂等与并发：

- 普通分析缓存键包含热点 ID、Provider、模型、提示词/Schema/分析版本及实际材料内容指纹；仅后台记录时间等无关元数据不应造成缓存失效。
- 材料中的事实/指标/趋势或分析版本有实质变化时形成新版本，页面明确提示未命中缓存。
- 相同缓存键已有成功分析时直接读取，不发请求、不新增付费运行记录。
- 相同缓存键正在执行时，其他点击/会话只展示进行中；SQLite 事务及唯一约束阻止并发重复请求，不只依靠 Streamlit session_state。
- 主动重新分析明确提示费用，使用独立动作 ID 追加新分析；同一确认动作的重复提交仍幂等。
- 异常中断的任务不会在重启时自动重发或自动释放未知费用；展示“状态待确认”，需用户在界面确认后重试，历史运行始终保留。

## 5. 候选筛选与调用范围

条件集中配置，默认每批最多 10 条：

1. 读取已有持久化评分，优先 A/B 均有效、未标记过期的热点，按现有综合分排序。
2. 过滤同材料/版本已有成功分析、正在执行或状态待确认的对象；数据不足不伪装成可靠趋势。
3. 正常候选仍展示评分和证据状态；旧评分过期时提示先使用现有离线重算功能，不在 AI 页面重渲染时自动重算或采集。
4. 手动选择允许分析候选外的已存热点，但要显示材料不足/评分过期提示；不需要为了分析而抓取新网页。
5. 一次批量操作显示实际候选清单、最多分析请求数、可能的重试尝试数、费用预占上界和可用预算，再由用户确认执行。
6. 批量按顺序执行，逐条返回成功/失败/缓存命中/预算不足；一个失败不伪造其他结果，也不自动扩大候选数量。

## 6. 费用估算与持久化预算

### 单价与配置

官方当前人民币价格可直接使用，无需臆造美元汇率。推荐初始价格表采用 `deepseek-flash` 高峰单价作为保守估算：每百万输入缓存命中 0.04 元、未命中 2 元、输出 8 元；价格版本记录为本次核对日期及“高峰保守估算”。即使实际处于空闲时段，也明确标注这是上界口径估算，不能冒充最终账单。

- 模型、输入缓存命中/未命中价、输出价、价格币种及版本通过配置读取。
- 允许使用其他配置价格；切换模型必须有对应有效价格表，不能沿用旧模型价格。
- 价格币种为 CNY 时直接计算；使用 USD 等外币时必须显式配置换算人民币的汇率，不内置虚构的固定汇率。缺少有效价格/汇率时阻止新的付费调用，原有功能仍可用。
- 每次调用冻结当时的单价、币种及汇率，之后改配置不改写历史估算。
- 成本使用 Decimal/整数货币单位处理，避免浮点累积绕过阈值。

### 计量与预算

- 优先解析服务商 usage：输入总量、输出总量及可用的缓存细分。缓存细分缺失但总输入已知时，按全部未命中保守估算并说明；完全缺失 usage 时 Token/实际估算费用留空，不赋零。
- 月份以北京时间 `Asia/Shanghai` 划分，数据库时间统一 UTC；默认月上限 100 元，70% 警告、90% 高风险、100% 禁止新调用。修改上限必须由用户保存并记录，重启不会恢复默认从而绕过限制。
- 每次 HTTP 尝试前用 `BEGIN IMMEDIATE` 原子检查并预占上界金额，预算口径为“已有用量估算 + 未结算预占”。达到上限或本次预占会超额时，在发送请求前拒绝。
- 通过输入字节上限、请求包装保守余量、`max_tokens` 及较高适用单价估算单次预占；每次重试也必须重新检查和登记，不在 Provider 内部进行不可见重试。
- 有完整 usage 时据此结算并释放多余预占；失败但返回 usage 仍记费用。usage 不明、读取超时或进程中断则保留预占，显示“费用待确认”，不假设免费，也不自动释放。
- 费用待确认时提供明确的人工核对流程，记录调整原因和动作；不能通过删除运行记录或切换页面清零。未核对前保持保守预占。
- 界面分别展示本月真实 Token 汇总（不完整时说明）、usage 估算费用、待确认预占、预算占用和可用余额，均不称为最终账单。
- 本地预算约束基于所配置价格和保守预占；服务商价格调整或未回报计费无法由本地系统证明最终金额，需结合服务商账单核对。
- 预算耗尽、没有密钥或 AI 服务不可用时，原有采集、排行、重算、历史和已生成选题查看继续运行。

## 9. 测试覆盖与最终验收

使用 Mock Provider/模拟 HTTP/临时 SQLite，不依赖外网或真实密钥。至少覆盖附件的 17 类场景，并补充：

- 同缓存键跨会话并发、同强制重分析动作重复提交；旧分析和选题状态保留。
- API 有 usage 但结构非法、无 usage 的失败、请求超时状态不确定、进程中断后预占保留、重试逐次记账。
- 连续点击、程序重启、月底跨时区、预算下调/上调、请求预占将超预算时拒绝、单价/汇率配置缺失。
- Provider 更换或版本变化使缓存失效；无密钥不影响原有功能。
- 迁移后前两期数据和 A/B 评分不变；未知数据库版本不静默打开。
